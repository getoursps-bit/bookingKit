## Notes for the server agent

This release **changes the database schema and adds seed content**, so the
three database steps run before the switch. Everything else is the usual
`bin/ffctl deploy`.

1. Wait for the pull request from `build/v1` to `main` to be merged and for
   CI to publish the image for the merge commit. Use the full sha:
   `git fetch origin && git rev-parse origin/main`.
2. Migrate with the **new** image before switching. Expect `--check` to list
   `0013_staff_email_code.sql` and nothing else.

   ```sh
   cd ~/Containers/fluffyfur
   TAG=<merge sha>
   IMG=ghcr.io/getoursps-bit/fluffyfare:$TAG
   docker run --rm --env-file .env --network <network> $IMG node worker/migrate.js --check
   docker run --rm --env-file .env --network <network> $IMG node worker/migrate.js
   docker run --rm --env-file .env --network <network> $IMG node worker/seed.js
   ```

   Migration 0013 only adds three columns to `staff` and widens the
   `message_outbox` kind check. It touches no rows. The seed only fills what
   is empty, so the owner's edited texts are kept; it is needed this time
   because the login email template is new. Without it, "Log in with a code
   by email" answers "the email could not be sent".
3. Switch: `bin/ffctl deploy $TAG`, then `bin/ffctl status`. Check that the
   worker moved to the same tag; the worker is what sends the login email.
4. No environment variable changes. The email login shows only because the
   email provider is already configured; nothing to add.
5. Smoke test on the live site:
   - `/healthz` answers 200.
   - Home page (`/` and `/en`): cream background, arch photo, free times as
     pills, pink services band, dark footer. The social pills appear only
     after the links are set in the owner area under Content → Salon details.
   - `/admin/login`: the page offers "כניסה עם קוד באימייל". Enter the owner's
     email, the code arrives by email within a minute, and the code opens
     `/admin`. The usual password + authenticator login still works.
   - Book once and confirm with the code, as before.
6. Tag the merge commit `v0.2.0`.

## Rollback

`bin/ffctl rollback` (or `bin/ffctl deploy a790d0e0796b5b9fabd77772150f2245927d36a2`)
returns to the previous version. Migration 0013 only adds things, so the
older version keeps running on the newer database. The extra `staff_code`
rows in the outbox, if any, are ignored by the old version. No database step
is needed to roll back.
