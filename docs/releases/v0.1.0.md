Date: 2026-10-28.

feedback. This is not the launch: Dibs stays in use until the switch day in
`docs/launch-checklist.md`.

## What the client can try

**Public site** (Hebrew at `/`, English at `/en`):

- Home page with services, opening hours, products, gallery and how booking
  works.
- Booking in four steps: pets, time, details and code.
  - The home page's "first free time" button carries that time into the
    booking.
  - The code goes by email, because WhatsApp is not set up yet.
- Private link `/b/<token>` from the confirmation email: see the booking, move
  it, cancel it, and turn messages on or off.

**Owner area** (`/admin`, login with an authenticator app):

- Today.
- Calendar: day, week and month, drag to move, click a free time to book.
- Inbox, customers and stats.
- Services, products and gallery.
- Opening hours and time off.
- Settings.

## Known limits in this preview

- **No WhatsApp yet.**
  - Codes, confirmations and reminders go by email, so the booking form asks
    for an email.
  - The WhatsApp button on the site shows only when the salon's chat number is
    set in Settings.
- **Content is placeholder until the owner fills it in.**
  - Before sending the link, set in the owner area: the salon phone and
    address, cover photo, logo, real opening hours, services and prices.
  - Without a salon phone, the "call the salon" buttons do not show.
- **Pet photos and AI analysis are off.** They need storage and the AI
  settings (see the guide).
- **Legal text is a draft.** The privacy and accessibility pages wait for
  legal review (open question Q7).
- **Some gaps remain open** in `docs/drift/2026-10-28_DRIFT_REPORT.md`:
  - no note per pet when booking;
  - product photos cannot be uploaded;
  - the gallery cannot be reordered;
  - the noindex header is set at build time.
  - None of them blocks trying the site.

## Release steps

1. Push `build/v1` and open a pull request to `main`. CI runs lint, typecheck,
   the tests and the image build.
2. Merge. CI publishes the image for the merge commit.
3. Ask the server agent to run `bin/ffctl deploy <full merge sha>`.
   - No migration or seed is needed: no `db/` files changed since `f431aef`.
   - If `node worker/seed.js` was never run after migration 0011, run it once,
     so English messages exist.
4. Smoke test on the live site:
   - `/healthz` answers 200.
   - Book once with your own email and confirm with the code.
   - Move the booking from the email link; the link still works afterwards.
   - Log in to `/admin` and see the booking in Day, Week and Month.
5. Fill in the salon content (above), then send the client the feedback guide.
6. Tag the merge commit `v0.1.0`.

## Rollback

`bin/ffctl deploy f431aefe38afbfd0a5142430c3e02e7885fc1ec0` returns to the
previous version. No schema changed, so no database step is needed.
